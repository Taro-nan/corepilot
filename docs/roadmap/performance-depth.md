# 性能工程深度改进清单

更新：2026-10-30。前四项的覆盖清单/错误实现检验、统一 Runner 队列、版本化统计区间/A/A、客户摘要与干净复现入口已经接入现有主线。下列复选项区分已实现能力和剩余验收，具体操作见[性能可信度与复现](../guides/performance-assurance.md)。本轮本地测试/RPC 夹具不代表新增飞腾硬件性能结果。产品路线遵循根目录统一的[开发宪章与工程指南](../../AGENTS.md)。

目标：客户能独立获得有正确性依据、性能结论可信、可以恢复和复现、能够采用的优化交付。以 Time to Peak Performance、有效收益、机器/模型成本及人工投入共同衡量。

## 交付顺序

| 顺序 | 工作 | 完成信号 |
| --- | --- | --- |
| P0 | 测试方案的辨别力 | 正确实现通过，选定的域内错误变换被识别；覆盖范围与未知项可解释 |
| P0 | 测量资源协调 | 本系统的构建、试跑和性能实验不会相互污染正式测量 |
| P0 | 真实统计区间 | 原始样本能重算结论，改善、退化、证据不足有依据 |
| P0，贯穿上述工作 | 客户报告、恢复与可复现交付 | 清楚说明推荐结果和下一步，干净构建可以复现交付 |
| P1 | 预算内深入搜索 | 保留最佳候选，可在达标后继续探索，最终候选独立复验 |
| P2 | 跨任务经验闭环 | 有来源的经验进入新调查，并用对照任务衡量收益 |

每项按独立完整切片实施；不要求一次实现全部，也不因此新建优化运行时。

## 1. 测试方案的辨别力

现有基础：AI 起草、代码预览与下载、Runner 两库试跑、版本绑定的人类审阅，见 [validation-review-service](../../src/application/validation-review-service.ts)。

- [x] 提供 API 语义覆盖清单、逻辑输入引用、依据和 UNKNOWN/不适用状态；由用户/模型按具体函数填充。
- [x] 分开呈现逻辑输入、执行矩阵和采样次数，避免用重复执行数冒充覆盖度。
- [x] 使用原正确性程序执行声明的已知错误实现；有效 FAIL 才算识别，配置的错误检验进入资格审阅。本地实际执行已验证漏算尾部、错误程序和崩溃的区别。
- [x] 正确性参考/容差与性能比较基线分别保存和显示，模型建议仍需试跑与审阅。
- [x] 用例/输入生成规则、seed、覆盖依据和支持文件可保存反例；已审阅资产只读，新版本重新试跑与审阅，旧记录不改写。
- [ ] 在实际目标库建立更多错误控制，并把发现的反例影响范围接回历史结果建议；一键派生已获资格方案为新版本尚未提供。

验收：选定错误能够被稳定识别，正常实现能够通过，每条结果可追溯到实际被测代码和判断依据。这是测试辨别力的验证，不宣称穷举正确性。

## 2. 测量资源协调

现有实现：[ExperimentExecutor](../../src/runner/experiment-executor.ts) 的单 Runner 持久 FIFO 队列复用原实验和 SQLite 记录；首版按整个实验独占。

- [x] 同一 Runner 的构建、开发 benchmark、profiling、资格试跑及正式测量共用独占队列。
- [x] 持久化资源占用与等待原因；重启和 UNKNOWN 保留占用，维护者停止确认独立留存，不改写历史。
- [x] 页面和 CLI 显示排队、准备、测量阶段以及资源等待时间。
- [x] 按平台能力记录前后系统负载、可用内存和 CPU0 频率等信息；不可获取字段为 null，不推断其他测试核。
- [ ] 在目标机验收真实构建、开发和正式实验并发提交；外部作业和多个 Runner 实例不由此队列统一协调。

验收：同时提交多个任务，测量时段及互斥条件可以从记录核对；取消和重启不会导致重复执行或永久占用。

## 3. 真实统计区间与测量校准

现状：[evaluatePerformanceGate](../../src/workspace/validation-runner.ts) 保留历史 gate v2；显式启用统计的新方案使用 [paired-block-bootstrap-v1](../../src/evaluator/performance-statistics.ts) 和 gate v3。

- [x] 按固定采样和相邻配对分块计算区间，保存方法、参数、seed 与样本摘要；重复/缺失/无效样本不能通过。
- [x] 总体区间对应固定权重几何平均；逐负载区间校正多负载比较，分别检查非退化和关键下限。
- [x] 测试条件保留计时范围、预热、每样本调用次数与两端执行顺序，并向实际测试代码传递。
- [x] 提供网页与 CLI A/A 同产物校准入口，独立于优化收益与两库资格试跑；首轮和复验不混合。
- [ ] 在飞腾目标机多轮 A/A 衡量噪声与经验误报率，并用独立 A/B 复验检查稳定性；单次本地 A/A fixture 不构成该证明。
- [x] INCONCLUSIVE 保存候选并停止验证，不追加模型修复或自动反复加测；采样条件改变需新测试版本。
- [x] 新口径使用新版本；历史点估计、资格和证据保持原含义。

验收：报告区间能从保存的原始样本重算，缺样本不产生确定收益结论，首轮与独立复验的差异可解释。

## 4. 客户报告、恢复和交付

现有基础：任务继续、冻结候选重新验证、实验/命令/样本导出、源码 tree 核验和人工交付。

- [x] 共享客户摘要展示当前候选、范围、首轮/复验、区间、退化、等待与下一步；缺有效独立证据不推荐交付。
- [x] 按实际输入参数、线程和绑核分组，标明描述性口径。
- [x] 恢复入口区分会话继续、冻结候选重验和原远端作业对账；系统故障不要求修改算法源码。
- [x] 网页与 CLI 在原机器的新目录重建冻结 Git 源码，复用原 RPC 计划与固定身份，追加独立实验与样本；中断继续核对同一 ID，不调用模型。
- [x] 源码交付提交/tree/候选/显式说明持久化，报告分别显示测试方案审阅、现有领域批准和交付事实。
- [ ] 统一公开 Evidence Freeze 与领域 Approval 操作入口；当前工作流合并不冒充领域批准。
- [ ] 在原飞腾机器对一个客户任务完成真实干净重建、人工审阅和交付验收。

验收：客户按公开文档和命令，在声明环境中重建交付版本并复现实验；无需直接改数据库或找临时脚本。

## 5. 预算内深入搜索

现状：[公开 Agent 主线](../../src/workflow/public-agent-workflow.ts) 已有持续会话、开发调查、假设和候选反馈，首个通过独立复验的候选即进入待审阅。

- [ ] 明确快速达标与预算内继续探索的目标，报告实际搜索范围。
- [ ] 持久化当前最佳有效候选及其证据；后续失败和中断不丢失它。
- [ ] 根据小尺寸开销、计算吞吐、访存与线程扩展等真实证据选择下一次实验。
- [ ] 将预期机理与观测结果关联，减少无新信息的重复候选。
- [ ] 开发测量用于筛选；候选选择结束后的独立复验支持最终结论。

验收：相同预算与任务集下比较达到目标的时间、最佳已验证收益、实验次数和成本，而非只比较模型调用次数。

## 6. 跨任务经验闭环

现有基础：Task/Hypothesis/Candidate/Experiment/Measurement/Outcome 历史事实。当前任务历史复用不等于跨任务飞轮已经实现。

- [ ] 从真实结果提取有稳定来源键的经验候选，区分事实和模型解释。
- [ ] 按算法类别、硬件、编译器、输入规模和资源条件检索有界摘要与证据。
- [ ] 在调查和假设提出阶段记录经验引用及采取的行动。
- [ ] 新结果追加支持、反例与适用范围，不覆盖原始实验。
- [ ] 通过隔离来源的任务集比较启用/禁用经验的效果，记录时间、成本和重复失败。

验收：能够证明某条经验在什么条件下减少了重复工作，不能仅以检索命中率证明价值。

## 一个真实函数的客户验收路径

选择已有函数和目标机，依次验证：API 契约与测试辨别力 → 资源受控的 A/A 校准 → 有效候选及独立测量 → 中断/恢复 → 人工审阅 → 干净重建与复现。按这条路径逐项关闭缺口，再扩大覆盖。
