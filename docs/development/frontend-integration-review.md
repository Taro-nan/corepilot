# 网页联调与使用流程改进

日期：2026-10-23。基于实际浏览器操作、HTTP 请求与保存结果核对；继续使用原有 Control、SQLite、优化入口和报告生成器。

## 本轮修复

| 操作场景 | 原先的问题 | 修复后的行为 |
| --- | --- | --- |
| 无项目时进入模型与机器 | 显示任务列表，缺少配置入口说明 | 显示项目接入引导，直接打开添加项目表单 |
| 添加项目、创建任务、源码交付失败 | 错误 toast 位于原生弹窗后方 | 错误显示在对应弹窗内，保留输入，支持修正与重试 |
| 高级配置切换标签 | 已编辑 JSON 未应用到表单，返回时被覆盖 | 合法修改同步到表单；无效 JSON 保留在编辑器并指出问题 |
| 编辑后离开配置页面 | 修改未提示且被丢弃 | 显示未保存状态；当前会话内按项目保留草稿；可保存或放弃重读 |
| 配置读取或报告读取失败 | 无限加载或误显示空列表 | 显示明确错误与重试入口，任务链接不会退回成任务列表 |
| 服务器断线 | 每次轮询反复弹出错误，易误认记录仍在更新 | 明确显示连接中断，保留上次记录，自动重连并可手动重试 |
| 修改优化函数后做运行前检查 | 仍检查配置中的默认函数 | `/v1/projects/:id/check` 接收 `function_name`，与实际提交目标一致 |
| 从源码目录导入相对配置路径 | 相对服务进程工作目录解析 | 相对所选源码目录解析；绝对路径保持原义 |
| 已结束任务显示进度 | 无效/未完成步骤仍显示为当前执行步骤 | 结束任务不再显示正在执行，待人工审阅单独定位到审阅阶段 |
| 首次网页加载 | 请求缺失的 favicon，控制台报 404 | 随发行包提供同源 SVG 图标 |
| 浏览源码目录 | 目录列表挤在项目表单中，导航、选择和确认混杂 | 独立文件夹选择器：固定侧栏、前进后退、路径编辑、搜索、单击选中 / 双击进入、独立列表滚动和固定确认栏；默认从服务启动目录浏览 |
| 选择源码分支 | 不能查看或选择，只取当前检出版本 | 添加项目选择默认分支，任务可覆盖；固定提交、独立优化和向所选分支交付，网页 / CLI 共用 |
| 已有配置文件 | 不清楚文件含义和是否必填 | 默认折叠导入入口，说明首次使用无需文件、可复用的配置内容和后续保存行为 |
| 新项目运行前检查 | 自动写入不存在的 `testpacks/domain.yaml`，预检返回底层 ENOENT | 新项目构建和验证均显示待配置，可分步保存；缺失方案和路径错误分别给出中文说明与配置入口，真实方案准备好后才允许提交 |

配置草稿仅保留在浏览器当前页面会话的内存里，不写入 localStorage/sessionStorage。切换项目和页面可继续编辑；刷新页面会清除未保存草稿。保存成功后继续使用后端脱敏配置，显式退出登录清除内存草稿。

模型列表、工具调用测试、SSH 测试与运行前检查会先保存当前配置，界面显示正在执行的动作。执行期间禁用配置编辑，避免检查中的参数与表单内容不一致。检查结果就地显示，不代表执行了构建、性能测量或资格审阅。

## 验证口径

- 使用实际浏览器覆盖项目接入、模型配置、目标函数检查、优化、源码差异、报告下载及人工交付；保持原有网页与 CLI 互通验证。
- 通过真实后端拒绝过期基线的交付请求，核对弹窗错误可见且源码没有变动，再验证修正后的交付。
- 使用网络故障注入验证断线与恢复、配置读取失败与重试；故障注入只用于隔离的测试实例。
- 验证配置保存前后的文件内容与凭据掩码，检查未保存凭据不进入浏览器持久存储。
- 使用真实 Git 分支验证任务来源、报告、CLI 覆盖与交付目标；原目录的分支、HEAD 和未提交文件保持原状。验证目标分支已前进、目标工作区有修改时拒绝交付。
- 验证文件夹单击选择与双击进入的区别、前进后退、最近项目、错误路径恢复、取消后保留原表单、键盘选择，以及 215 个子目录在 390×640 窗口下的滚动和确认按钮可见性。
- 验证空验证方案可保存，预检和任务提交均拒绝未配置或缺失的 testpack；补齐真实测试方案和构建后预检通过，准备过程不创建工作流或伪造测试文件。
- 浏览器完整优化流程使用离线模型协议和命令夹具，不能作为新的真实模型或飞腾硬件性能结论。

运行命令沿用 `npm run typecheck`、`npm run build`、`npm test`、`npm run test:web` 和 `git diff --check`。测试页面截图位于 `build/frontend-audit/`；测试夹具和真实日常项目分开保存。

## 文件夹选择器的交互参考

采用成熟文件选择器的空间结构和操作习惯，参考 [Windows 文件夹选择器](https://learn.microsoft.com/en-us/windows/apps/develop/files/using-file-folder-pickers)对当前位置、所选项目和位置导航的说明，以及 [Google Picker](https://developers.google.com/workspace/drive/picker/guides/web-picker)的应用内弹窗方式。工程工具的侧栏导航参考 [VS Code 界面](https://code.visualstudio.com/docs/editing/getting-started/userinterface)。

CorePilot 选择的是服务器可读取的目录，因此使用现有 `/v1/directories` 接口，通过 React 实现选择器。最近项目复用已有项目记录，路径和文件夹名称来自实际目录读取。
