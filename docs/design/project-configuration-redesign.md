# 项目配置与任务创建：体验设计方案

本文记录项目配置与任务准备的设计方向；尚未落地的目标和当前限制在下文注明。设计依据是对现有代码及本地工作台的只读检查；未启动优化、试跑或交付。

## 目前的实际问题

- 项目概览、任务表单和构建与验证分别选择或展示分支、机器与函数，默认值和本次任务选择的作用范围不够直观。
- 当前 BLAS_FT 概览显示目标 `cblas_dtpsv`，现有测试方案却属于 `cblas_ztrsm`；从概览进入“准备构建与验证”后仍停在后者，需要用户自己找回原目标。
- 点击创建任务时，若当前方案未获资格，页面直接跳到构建与验证；项目、目标与原操作意图没有作为清晰的返回上下文展示。
- 构建与验证同时承载接入方式、跨项目方案列表、构建、基线、测试条件、代码与试跑，新用户很难判断当前缺哪一项。已配置、已试跑、已获资格也容易混淆。
- 接入库一次需要准备的内容，与每个函数单独需要准备的测试资产混在一起。更换函数时，用户不清楚哪些内容可以沿用、哪些必须重新确认。
- 不同页面的草稿与保存时机不同；用户需要自己记住操作位置、返回方式及哪些更改已保存。

相关实现入口：[项目概览](../../web/src/ProjectOverview.tsx)、[任务创建](../../web/src/TaskComposer.tsx)、[构建与验证](../../web/src/BuildValidation.tsx)、[页面导航](../../web/src/App.tsx)和[准备状态](../../src/application/project-setup-service.ts)。

## 设计目标

工程师从当前项目出发，始终能看到“优化谁、在哪台机器上、依据什么验证、现在缺什么、下一步做什么”。首次接入可以分阶段完成；条件已齐备时，在一个任务确认页直接复用，不重复经过接入向导。

项目默认值只用于预填，用户可以为单次任务更改。正式提交时冻结实际选择；后续更改默认值不改写既有任务及证据。

## 推荐的信息结构

```text
项目概览       当前上下文、准备状态、继续中的工作、最近任务
优化任务       选择目标、准备构建与测试方案、运行、审阅交付
项目设置       源码与默认分支、模型及默认机器
系统管理       注册和维护机器、连接与诊断
```

构建与验证是任务准备的一部分；项目概览可直达当前目标的准备入口，方案与基线仍作为项目资产保存并复用。实验分析和优化报告继续保留访问能力，可以从任务详情直达。无需以此结构新增一套后端；旧的 `#/validation` 和 `#/settings/validation` 链接继续可用。

## 项目概览

```text
BLAS_FT                                               [创建优化任务]
分支  fix/…     机器  S5000C     目标  cblas_dtpsv       [均可更换]

当前目标还需要测试方案
已有构建设置 · 机器最近检测在线 · 当前测试方案属于 cblas_ztrsm
[为 cblas_dtpsv 准备测试方案]    [查看现有方案]

正在进行 / 等待处理    （没有时简短显示空状态）
最近任务               （少量记录，查看全部）
```

主要按钮根据真实状态指向“继续准备”“创建优化任务”或“查看任务”。准备项应显示具体缺口而不是笼统地说配置不完整。概览中的可编辑项要标明“项目默认值”；任务中的临时更改不自动覆盖默认值。

## 函数与测试方案

选择函数后，以当前项目和函数查找已有测试方案，展示方案名称、适用函数、来源、版本及状态：待完善、待试跑、待审阅、已验证可用、失效或待核对。只推荐具备明确关联依据的方案；没有匹配项时直接提供“准备此函数的测试方案”，保留所选函数。

方案准备采用清晰的工作区，而不是一次展示全部表单：

1. **构建当前库**：沿用项目已有构建方式，展示来源和最近验证结果；用户可修改或确认。发现的命令只是建议。
2. **选择比较对象**：已有版本、另一分支构建或导入外部库三选一。固定后显示库版本、来源与产物；切换方案时重新核对 API、产物和兼容性。
3. **正确性与性能测试**：有现成代码就上传或复用；没有可让 AI 起草。展示测试输入、参考结果及误差、性能负载、线程与绑核、采样；低频细节可展开。AI 生成的代码仍为草稿。
4. **试跑与确认**：显示当前具体缺项、执行过程、结果和审阅入口。配置保存、试跑完成、结果通过和方案获资格分别表达。

这些是准备内容而不是强制每次重走的顺序：用户可以先接入正确性测试；要进行两库性能比较时，必须先固定适用的比较对象。已经完成的内容可以复用，但要展示其依据和适用范围。

已有方案允许查看与复用，但必须保持其冻结身份；修改规则或基线后生成新的适用身份，不能把旧试跑与资格直接套到新内容。每个函数可以有不同方案、基线及正确性规则，不能只改函数名复用测试。

## 创建任务

已有可用方案时，一个页面完成确认：

```text
创建优化任务
项目 BLAS_FT  ·  分支 fix/…  ·  机器 S5000C              [更换]
目标函数  [搜索、选择或输入函数]
测试方案  [已选择的匹配方案及状态]                        [查看/更换]

比较对象  KML 2.0（示例）
测试范围  输入与尺寸 … · 线程 1/2/4/8 · 绑定 … · 误差 …
测量方式  预热 … · 每端采样 … · 计时范围 …
高级设置  时间与候选预算、优先调查文件等                 [展开]

[运行前检查]                                  [开始优化]
```

没有方案或状态未满足要求时，在同一页面明确原因与“准备该函数的测试方案”。进入准备页面时携带项目、函数、分支、机器和返回位置；完成或取消后回到原任务草稿。不得把自动匹配当成资格证明，多个匹配方案应由用户明确选择。改变测试方案或基线时，显示会受影响的条件供用户核对。

提交前显示影响正确性、负载范围、资源、比较基线和结果解释的关键条件；检查不会声称实际构建、正确性或性能已通过。模型和机器的连接诊断按需展开。

## 跳转、保存和反馈

- 在准备任务过程中进入其他页面，始终提供“返回任务配置”；返回后恢复之前输入，清晰标明哪些已保存、哪些仍为草稿。
- 同类设置有一个权威来源，其他入口是对同一配置的编辑；保存时标注“项目默认”或“仅本次任务”。与其他未保存更改冲突时提示处理，不能覆盖。
- 用户选中其他 Git 分支时，源码识别必须标明依据的是哪个提交。现阶段已有识别读取当前工作区，不能把它说成已识别所选其他分支；针对固定分支的识别需要后端支持。
- 长操作显示真实状态、错误及可继续操作；错误就地说明原因和下一步，完整日志按需查看。浏览器关闭不等于取消后台作业。
- 保留高级设置、脚本查看下载、产物与身份信息，但将其放在有明确名称的展开区域或详情中。

## 需要补齐的实现边界

当前项目配置主要保存一个选中的测试方案；概览的默认函数与方案选择分开。共享应用服务按项目和函数列出可关联的自建或已绑定方案及其状态；选择方案不等同于取得试跑资格或正式批准。Web 和 CLI 共用查询结果与既有的配置、验证服务。

外部方案目前只保存当前绑定，尚无项目级外部绑定历史；首次选择其他外部方案时，从任务准备中的完整目录入口核对并绑定。不会把其他项目的方案自动推荐为当前项目资产。

任务草稿与项目配置应区分：任务输入保存在当前浏览器会话，包含函数、分支、机器和预算，不保存明文凭据；配置与方案由各自的现有服务管理。任务提交和验证资格依旧以服务端检查为准，不重建工作流状态机。

未保存的项目配置与测试编辑留在网页内存；任务准备页和其他页面往返可恢复，刷新、关闭或退出前会提示。高级 JSON、待添加参数和自定义线程输入须先应用，再保存或试跑。服务端版本发生变化时保留输入并提示核对，保存仍通过版本摘要检查。

源码识别当前针对检出工作区；要对其他分支给出可信函数列表，需增加按指定提交只读识别与身份记录。无此能力时继续提示用户核对，不假装已经验证。

测试代码生成和方案试跑当前仍使用项目默认分支及项目默认机器，不自动继承任务中临时选择的环境；准备界面需显示差异，分支基线构建则使用其单独选择的分支。正式任务使用其测试方案中的构建定义，项目通用构建命令不能代替最终构建依据。

## 建议的交付顺序与验收

1. **修正断点**：从概览或任务入口准备测试时，目标和返回位置保持一致。以 BLAS_FT 的函数不匹配为例，从 `cblas_dtpsv` 出发不得默认编辑 `cblas_ztrsm`；返回后原表单保留。
2. **理清配置所有权**：分支、机器、函数分别标明项目默认与本次任务；方案按项目和函数查找，明确当前使用哪一份；不同项目或函数的旧方案不能被误选。
3. **重排准备过程**：按构建、比较对象、测试、试跑与确认组织复杂接入；成熟项目保持单页任务确认。验证保存、刷新、失败、返回和低频能力仍可找到。
4. **优化视觉和细节**：统一标题、间距、状态、焦点、错误及窄屏布局；在真实后端只读路径和独立夹具中分别验证，不把夹具结果当真机实验。

实施后应验证 Web/CLI 共用配置与资格判断，旧项目和旧任务无需重建；不启动真实远程优化，也不执行批准或交付来验证界面。
