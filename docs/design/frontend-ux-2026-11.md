# 主路径体验整理

本轮围绕「项目与机器 → 配置任务 → 执行 → 理解结果 → 人工处理」调整现有 React 工作台，沿用现有应用服务、配置与事实来源。

## 实际观察

- 概览的五张统计卡、教程、配置路径和四个并列操作挤占首屏，没有结合项目准备情况给出下一步。
- 创建任务缺少直接选择机器和完整的提交条件摘要；预算折叠后看不出已修改值。
- 任务详情同时展开长过程、阶段证据、内部标识、实验表和复现操作；执行、验证与交付的状态不够容易区分。
- 历史交付缺少新的 delivery 身份记录时，报告仍建议再次审阅，需要明确历史交付记录和当前可核验的交付身份。
- 模型连接的常用字段与代理、推理、调试配置混排；构建与验证重复解释较多。

## 实施切片

1. 共用的渐进展开、标识复制、错误详情与统一视觉；保留原有设计和原生键盘行为。
2. 概览展示真实准备状态、下一步和近期任务；配置及内部身份按需查看。
3. 创建任务复用已有配置，集中选择目标、分支与机器；提交前展示测试范围、资源、基线和预算。
4. 执行页优先阶段、等待原因及恢复动作；结果分开呈现执行、正确性、性能、批准和交付。完整日志、历史实验及原始样本按需展开。
5. 设置和验证页面区分常用配置与维护入口，高级设置折叠后仍显示当前取值或已调整标记。

## 验收

浏览器核查真实后端只读路径；独立 fixture 核查配置保存、表单校验、刷新、导航、折叠、键盘、加载/失败/断线、执行与结果展示。检查桌面、笔记本和窄屏布局，输出截图。执行类型检查、构建、仓库检查和适用测试。

本轮不启动真实硬件优化或复现实验，不执行批准、合并和交付。不改写历史证据，不把夹具演示称为真机验证。

## 本轮结果

- 已完成上述五个切片，复用原有路由、应用服务、配置、持久会话和实验事实。
- 类型检查、构建、仓库检查通过；完整后端 237 项、浏览器 40 项测试通过。浏览器新增覆盖高级值摘要与保存、任务草稿恢复、隐藏字段校验、焦点返回、筛选刷新、无效实验与排队进展。
- 真实服务只读核查项目概览、任务配置、模型设置和构建验证；另以独立 fixture 验证执行、失败、恢复及结果。截图位于本次本地构建产物中，不把模拟记录计入真实实验。
- 新增的后端支持只有任务机器覆盖检查、只读比较基线展示信息及历史交付身份待核对状态。没有增加并行业务系统或改写已有证据。
- 当时停止和重启本地后端曾被自动审批拒绝；后续只读核查已确认服务加载了该轮后端改动。静态资源构建与后端进程更新仍是两个步骤，后续修改后应分别核对实际运行版本。
