# 优化与测试分离

## 目标与边界

优化负责产生源码候选；测试负责在指定机器上比较固定的两个对象。用户可以分别使用，也可以在优化时选择自动验证。比较对象可以是源码分支或上传的库包；没有源码的对象不能创建代码优化任务。比较基线不自动成为独立正确性参考。

本次沿用 Pi 会话、Runner 实验协议、固定测试方案、测量协议和统计模块，不复制执行器或正式判定。历史工作流缺省沿用原来的验证模式，历史证据不变。

## 已完成的实现

1. 明确的源码优化模式：无需测试资产，不启动实验，冻结候选与补丁，终态为“代码待验证”。正式审批和交付门禁保持有效；原会话可继续生成新的候选。
2. 独立测试用例：固定两端身份、机器和测试方案，支持正确性、性能及二者；记录准备、提交、执行与取消，断线后对账原作业。
3. 共享 HTTP / CLI 与网页：独立测试列表、创建和结果；任务创建可选择仅生成代码或自动验证。常用选择直达，完整身份和日志按需查看。
4. 隔离验证覆盖无测试优化、三种比较组合、文件上传、重复提交、取消、重启与旧路径兼容；本轮没有运行真实硬件实验。

## 交互与实现边界

任务创建主界面保留优化方式、函数、分支、目标机器与测试条件；预算和调查文件按需展开。源码模式每次提交一个完整候选，候选数筛选预算仅在自动验证模式显示。

测试创建主界面保留两端对象、测试内容、执行机器、方案及正确性参考、误差、线程和采样摘要。源码构建设置可展开并按次覆盖，提交固化实际显示的命令与方案版本。正确性单测可明确向脚本提供比较库，不自动授予其 oracle 身份。

结果页先显示执行、正确性和性能三种独立结论，再展示逐负载数据；日志、文件摘要、完整输入与机器身份按需查阅。测试准备结束后返回同一份测试草稿并重新读取方案目录，避免跳回优化流程或使用旧目录。

`testing-*` 分别管理输入、方案、两端准备、Runner 提交、结果读取、资产和持久记录；`source-*` 分开处理无评价器的输入、会话装配和候选冻结。两条路径共用既有 Pi、源码工具和 Runner，正式判定规则没有复制到网页或 CLI。

文件对文件目前复用已有的适用测试方案；AI 起草与脚本上传仍沿用项目测试准备入口。库包上传支持 `.so` 及头文件，其他二进制类型、无源码上下文的 AI 方案生成不在已实现范围。

## 接口与所有权

- `PublicWorkflowRequest.verification_mode`：`verified`（历史缺省）或 `source_only`；优化工作流和领域对象继续由现有优化服务持有。
- 独立测试对象使用判别联合表达源码或库包，不伪造 Git 候选。测试服务拥有请求、固定身份及准备状态；Runner 拥有命令、测量与执行事实。
- 独立测试是 `DEVELOPMENT_FEEDBACK`，结果明确非正式批准证据。执行完成、正确性通过和性能变化分别表达，不产生人工批准或交付记录。
- HTTP 与 CLI 仅解析输入、调用共享应用服务；网页不计算正式性能结论。

## 验收

无模型的两库测试可独立创建；有源码的对象可进入优化；高级条件不会被隐式随机生成；页面刷新后能找到任务、两端版本、机器、条件、测量和失败原因。源码模式的候选始终显示“正确性未验证、性能未测量”，不得进入正式批准或交付。
